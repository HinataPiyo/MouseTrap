# ゲーム概要・実装状況

## 作品概要

MouseTrapは、学校の部屋を探索し、人物や物品との会話・イベントを通じて進行する2D探索ゲームとして開発されています。現在のシーンやデータには職員室、図書室、隠されたヒント、人物との会話、物音を調べるイベントが含まれています。

リポジトリ内の実装だけでは、作品全体の物語、最終目的、エンディング、コンテスト提出時の完成範囲は確定できません。これらは仕様として別途確定し、ゲーム内のイベントと合わせて更新してください。

## 基本操作

| キー | 操作 | 補足 |
| --- | --- | --- |
| W / A / S / D | プレイヤーを移動 | 斜め移動は正規化されます。 |
| E | 近くの対象を調べる | インタラクト中に再度押すと、その操作状態を解除します。 |
| Space | 会話を進める | 文字表示中に押すと、その行の全文を表示します。全文表示後、次のSpaceで次の行に進みます。 |
| Tab | インベントリを開閉 | 開いている間は移動入力が止まります。 |
| Q | キャラクター情報を開閉 | 表示中は移動入力が止まります。 |
| 1～5 | キャラクター切り替え | 通常時またはインベントリ表示中に入力できます。解放状態にないキャラクターは切り替えられません。 |
| Escape | パネルを閉じる | インベントリ、キャラクター情報、部屋移動画面で使用します。 |

部屋移動は移動ポイントに触れると画面に表示されるボタンから行います。操作説明は`PlayerInputController`、`Movement`、各UIパネルの入力イベントに基づいています。

## 現在確認できるゲーム進行

1. プレイヤーを操作して部屋を探索する。
2. インタラクト可能な対象に近づき、表示されるマークを目印にEキーで調べる。
3. 対象に応じて会話、アイテム取得、イベントなどが発生する。
4. イベント完了によってキャラクターの操作や部屋への移動が解放される場合がある。
5. 部屋移動ポイントのボタンで、移動可能な部屋へ移動する。

これは現状のコードとデータから把握できる範囲です。ゲーム全体のクリア条件や、すべてのイベントをつないだ完成ルートが実装済みであることを示すものではありません。

## 実装状況と確認事項

### 実装されている仕組み

- WASDによるプレイヤー移動と移動アニメーション
- インタラクト範囲の検出と、対象に応じたイベント処理
- ScriptableObjectを使った会話データ、インタラクトデータ、ミッションデータ
- 会話UI、インベントリUI、キャラクター情報UI、部屋移動UI
- イベント完了状態に基づく通行止め解除
- フェードを伴う部屋移動
- イベントによる少年・眼鏡少年の操作解放

### 提出前に確認・完成させる項目

- **完成ルート:** 全イベント、ゲーム開始からクリアまでの進行、クリア条件・終了演出が一続きで遊べるかは、コードから確認できません。
- **キャラクター解放:** 1～5の入力は用意されていますが、コード上の解放イベントは少女、少年、眼鏡少年に限られます。不良少年とツインテールの少女の操作解放やデータ設定を確認してください。
- **部屋解放:** `SceneChangeManager`は職員室・図書室を起動時に移動可能としており、コードにテスト用設定の注記があります。イベント進行に沿った解放条件になっているか確認してください。
- **ミッション:** データ、表示、設定・完了処理はありますが、ゲーム進行との一貫した連携や達成条件は別途確認が必要です。
- **Build Settings:** `stage03`をゲームに含める場合は、シーン登録と部屋移動の対応を確認してください。
- **実プレイ確認:** 各シーンの参照設定、衝突判定、UI、イベント連鎖はUnity Editor上で通しプレイして確認してください。

上記はソースとBuild Settingsの確認で見つかった検証項目であり、Unity Editor上で発生を再現した不具合一覧ではありません。
